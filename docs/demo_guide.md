# Demonstration Guide

This guide provides the exact sequence of steps to demonstrate the Retail BDA Analytics Platform successfully during an academic presentation or viva.

## Demonstration Sequence

### STEP 1: Introduce Project Architecture
Open `docs/architecture.md` or present the architectural diagram. 
Explain that the project simulates a Big Data pipeline starting from raw data ingestion, batch processing via MapReduce, data warehousing via Hive, and visualization via a React/FastAPI stack.

### STEP 2: Show the Raw Dataset
Show the raw data file generated by the system.
**Action:** Open `data/retail_logs.csv` and point out the 13-column structure (Transaction ID, Category, Quantity, Price, City, etc.).

### STEP 3: Validate the Dataset
Prove the dataset's integrity.
**Action:** Run the validation script in the terminal:
```bash
python scripts/validate_data.py
```
**Point out:** The 5,000 records, total revenue (₹18,044,188.70), and the exact matching counts.

### STEP 4: Demonstrate MapReduce Processing
Explain how MapReduce aggregates metrics by processing the raw CSV.
**Action:** Run the MapReduce simulation:
```bash
python scripts/run_mapreduce.py
```

### STEP 5: Show MapReduce Outputs
Verify that MapReduce generated actual analytical output.
**Action:** Open `output/mapreduce/category_revenue.tsv` and show how the data is grouped.

### STEP 6: Explain HDFS and Local Fallback
Explain the role of distributed storage.
**Action:** Run:
```bash
python scripts/check_hdfs.py
```
**Point out:** "HDFS is unavailable in the current Windows environment. Therefore, the project gracefully uses a truthful local fallback to store raw and processed data."

### STEP 7: Show HiveQL Scripts
Show the schema-on-read implementation.
**Action:** Open `hive/create_tables.hql` and `hive/analytics.hql`. Explain that these SQL-like queries define how the Big Data warehouse would process the data.

### STEP 8: Run Hive Analytics / Fallback
Generate the complex analytical reports.
**Action:** Run:
```bash
python scripts/run_hive.py
```
**Point out:** Explain that the local fallback engine processes the data precisely as Hive would to maintain pipeline integrity.

### STEP 9: Start the FastAPI Backend
Start the serving layer.
**Action:** In terminal 1:
```bash
cd backend
python -m uvicorn main:app --port 8000
```

### STEP 10: Start the React Frontend
Start the presentation layer.
**Action:** In terminal 2:
```bash
cd frontend
npm run dev
```

### STEP 11: Present the Interactive Dashboard
Open `http://localhost:5173` in a web browser.
**Walk through:**
- **KPI cards:** Show Total Revenue matching the MapReduce output exactly.
- **Charts:** Point out the Revenue Trend, Monthly Revenue, and Category Analysis.
- **Engine Awareness:** Point out the badge at the top reading "Analytics Engine: LOCAL FALLBACK", proving academic honesty.

### STEP 12: Show API Endpoints (Swagger)
Prove the backend is serving the data dynamically.
**Action:** Open `http://localhost:8000/docs` in the browser and execute the `/api/analytics/summary` endpoint to show the raw JSON response.
