# Viva Preparation Guide

This document contains likely questions an evaluator might ask regarding the Retail BDA Analytics Platform, along with concise, technically accurate answers.

**1. What is Big Data?**
Big Data refers to datasets that are too large, fast, or complex to be managed by traditional relational database systems. It is characterized by the 3 Vs: Volume, Velocity, and Variety.

**2. Why is this project a Big Data Analytics project?**
It implements Big Data architecture concepts (MapReduce and HiveQL) over a retail dataset, structuring the data pipeline in a distributed-system compatible way, allowing the logic to scale infinitely if moved to a Hadoop cluster.

**3. What is HDFS?**
Hadoop Distributed File System (HDFS) is a distributed file system designed to run on commodity hardware, providing high-throughput access to application data and fault tolerance via block replication.

**4. Why is HDFS used?**
It is used to store massive datasets across multiple machines in a cluster, allowing computation to be moved to where the data resides rather than moving data over the network.

**5. What is MapReduce?**
A programming model and processing framework for distributed computing. It breaks a massive task into smaller sub-tasks (Map) and then combines the results (Reduce).

**6. What is a Mapper?**
A program/function that takes input data, parses it, and emits key-value pairs (e.g., extracting category as a key and revenue as a value from a transaction log).

**7. What is a Reducer?**
A program/function that receives the output from Mappers (grouped by key) and aggregates them into a smaller set of values (e.g., summing all revenues for a specific category).

**8. What is Shuffle and Sort?**
The phase between Map and Reduce where the framework sorts the mapper outputs by key and transfers them to the appropriate reducers so all identical keys are processed together.

**9. Why is MapReduce useful?**
It allows developers to write code for massive datasets without worrying about network communication, fault tolerance, or node failure handling, as the framework manages this.

**10. What is Hive?**
Apache Hive is a data warehouse software built on top of Hadoop that facilitates reading, writing, and managing large datasets residing in distributed storage using a SQL-like interface.

**11. What is HiveQL?**
Hive Query Language (HQL) is the SQL-like scripting language used by Hive to write MapReduce jobs in an easier, declarative format.

**12. Difference between SQL and HiveQL?**
SQL is designed for rapid row-level queries and ACID transactions on relational databases. HiveQL is designed for batch analytics and schema-on-read processing over massive, immutable distributed files.

**13. Why use Hive for analytics?**
Writing complex analytical queries (like calculating monthly revenue trends) in raw MapReduce Java/Python code is extremely complex. Hive simplifies this by abstracting the MapReduce jobs behind a familiar SQL syntax.

**14. What is the role of FastAPI?**
FastAPI acts as the Serving Layer. It reads the aggregated outputs generated by the analytics engine, structures them into strict JSON formats using Pydantic, and serves them over REST APIs to frontends.

**15. Why was React used?**
React allows the building of dynamic, component-based user interfaces. It was used alongside Recharts to build an interactive dashboard that visualizes the analytical JSON data efficiently.

**16. What is REST API?**
Representational State Transfer (REST) is an architectural style for providing standards between computer systems on the web, making it easier for systems to communicate using standard HTTP methods.

**17. How does the frontend receive analytics?**
The frontend utilizes the `axios` library to make asynchronous HTTP GET requests to the FastAPI endpoints, storing the received JSON in React state variables to render charts.

**18. How is total revenue calculated?**
In MapReduce, the mapper emits a hardcoded key (e.g., "TOTAL") and the transaction amount. The reducer iterates over all values associated with "TOTAL" and sums them.

**19. How is category revenue calculated?**
The mapper extracts the "Category" string from the CSV and emits it as the key, alongside the amount as the value. The reducer then sums the values grouped by each distinct category.

**20. How does the local fallback work?**
When the Python scripts detect that the `hdfs` or `hive` executables are missing, they bypass Hadoop execution. Instead, they use native Python libraries (like `csv` and `collections`) to replicate the exact aggregations Hive/MapReduce would perform, saving the identical TSV output files.

**21. Why is Hadoop unavailable?**
Setting up a multi-node Hadoop cluster is complex, resource-heavy, and often incompatible with standard Windows academic machines. 

**22. Why is Hive unavailable?**
Hive requires a running Hadoop cluster and HDFS instance, which are not installed locally.

**23. Is the project still valid without Hadoop/Hive execution?**
Yes. The project demonstrates the full logical architecture, pipeline flow, and integration of the Big Data stack. The local fallback ensures the end-to-end data flow (Raw Data -> Processed -> API -> UI) works, while preserving the exact HQL/Mapper scripts required for cluster execution.

**24. What are the limitations?**
The primary limitation is scale. The current local fallback engine processes data in memory using single-threaded Python scripts, meaning it cannot process terabytes of data like a true Hadoop cluster could.

**25. What are possible future improvements?**
Deploying the project to AWS EMR or a Dockerized Hadoop cluster, integrating real-time streaming via Apache Kafka, and utilizing Spark for faster, in-memory processing.
